# 用户自定义整理模板：Skill 设计建议

日期：2026-10-20（Asia/Shanghai）。状态：设计建议，尚未实施。

目标：允许用户按自己的用途定义如何组织口述内容，同时保持创建简单、结果可试用、规则可维护。本文根据本次读取的工作区实现提出增量设计，不改变已有产品代码或其他进行中任务。

## 1. 产品定义

面向用户继续使用“整理模板”：一份可以保存、编辑、试用、重复使用的文字处理要求。内部可以沿用 Skill 的名称和 ID。

默认任务是把本次口述提供的素材整理成用户需要的文字。用户可以改变结构、语气、语言、篇幅和排版，定义自己的栏目与固定表达。

如果以后支持“理解我的指令，直接创作内容”，应显式区分为另一种处理方式。整理素材与按要求生成对口述的解释不同，不能因自定义规则中出现某个词而暗中改变执行语义。首版无需为此增加复杂的任务编辑器。

## 2. 创建入口保持简单

| 编辑内容 | 必填 | 作用 |
| --- | --- | --- |
| 模板名称 | 是 | 用户识别和选择，如“客户拜访记录” |
| 整理要求 | 是 | 用自然语言描述想得到什么、如何组织、保留什么 |
| 适用场景 | 否 | 一句话说明什么时候使用；为将来推荐用途提供描述，但当前不承诺语义自动选择 |
| 参考样例 | 否 | 一组或少数组“原始口述／期望结果”，保存后可参与生成 |
| 输出格式 | 有默认值 | 默认纯文本；需要时切换 Markdown |
| 缺少信息怎么办 | 有默认值 | 默认省略无内容栏目，可选择标“待确认” |

用户可以只填写名称和一段要求就保存。结构、语气、受众、篇幅等可以通过占位提示引导填写，首版不必拆成多项强制字段。

保留“从空白创建”和“复制现有模板再调整”。内置模板与用户模板采用同一个执行契约；内置模板作为受应用维护的起点，复制后生成独立用户模板。

## 3. 一份示例模板

名称：客户拜访记录。

整理要求示意：

> 将我的口述整理为客户需求、已确认事项、下一步三个部分。措辞简洁，适合发送到工作群。保留客户名称、日期、金额、责任人，以及尚未确定的表述。没有内容的栏目省略，不推测客户决定或我方承诺。

样例输入：

> 今天见了蓝山公司，他们想增加批量导出。我答应周五给一版方案，上线时间还没定。

样例期望结果：

> 客户需求：蓝山公司希望增加批量导出功能。
>
> 已确认事项：我将在周五提供一版方案；上线时间尚未确定。

这份样例说明：提供方案与上线是两件事；明确未定的信息要保留；没有额外下一步素材时不机械增加栏目。样例为设计示意，未调用模型实测。

## 4. 应用和模板分别负责什么

应用统一执行模块负责：接收本次转写和选中的模板版本，组装请求，调用当前文字服务，处理取消、超时及输出结果。调用方只需提供本次材料和模板；不需要理解不同模型的消息布局。

模板负责表达任务要求、样例和格式偏好。模型提供商、密钥、ASR、录音及输入到哪里，由现有应用配置和本次调用管理。首版不要求每份模板单独配置模型。

全局规则保留与用途无关的要求，例如不凭空补充现实事实、保留数字和否定、保留不确定性、只返回任务结果。允许模板定义标题、栏目、排版、语言和语气。

“所有缺项都写待确认”“禁止任何标题”“全部保持口语”等不适合作为每份模板不可调整的全局要求。缺项策略由模板决定；整理规则允许添加标题、衔接语和用户指定的固定结束语，但不凭空增加现实事实或承诺。

事实保真等语义要求仍需要模型遵循与样本验证。消息角色和规则优先级用于表达契约，不能被当作语义结果绝对正确的保证。

## 5. 模型请求的组装

组装内容包含：应用通用规则、该模板的整理要求、输出及缺项策略、启用的参考样例、本次口述。

在支持相应角色的模型接口中，可将任务规则作为系统指令，将样例组织成 user / assistant 消息对，最后追加本次材料。不同接口的具体布局由统一执行模块处理。首版通常可以在一次生成请求中完成，不为每层规则额外调用模型。

样例应明确只是处理方式示范，不能把其中的客户名称、日期等事实带入本次结果。需要用不同人名、数字和日期的材料检查是否出现样例内容串入。

设置参考样例的数量和总长度预算。超过预算时给编辑器明确反馈；不要在保存成功后默默忽略样例。正文超长的处理应沿用应用的任务限制，不把需要整体组织的任务随意切成多个独立成稿。

缺项策略尽量采用一个明确的数据来源。选项编辑时同步更新说明；发现自然语言要求与选项明显冲突时，引导用户修改。语义冲突不可能靠字符串校验完全识别，最终以试用样本检验。

## 6. 样例与试用分开

- 参考样例：用户已认可的输入输出对，可进入后续生成请求。
- 试用输入：当前用于观察模板表现的材料，不会自动成为长期样例。
- 试用输出：当前模型生成的候选，用户修改并主动选择“保存为参考样例”后才加入模板。

编辑器可以让用户输入材料、试用、修改结果，并将满意版本保存为样例。保存样例后，用另一段材料再试，检查模板能否泛化。

试用与实际录音应使用同一套模板编译规则和文字模型选择逻辑；试用无需自动输入或保存为真实历史。这样试用结果才有参考意义。

## 7. 模板数据建议

在现有记录上增量增加字段，而非另起一套与内置模板不兼容的格式：

| 字段 | 用途 |
| --- | --- |
| id、source、name、description、instruction、outputFormat、enabled | 沿用现有模板概念 |
| examples | 经用户认可的输入输出对 |
| missingInfoPolicy | 省略空栏目或标待确认，明确默认行为 |
| schemaVersion | 文件结构版本，用于迁移 |
| revision | 模板内容的修订版本，便于定位试用与历史所用配置 |
| updatedAt | 用户实际修改时间 |

模板选择、快捷键绑定和结果去向单独保存，用稳定模板 ID 引用。修改名称不应使绑定失效。一次录音使用开始时固定的模板快照，编辑模板不改变已在途任务的规则。

后续增加选区或用户参考材料时，再增加明确的输入来源配置。模板描述中写“读取当前聊天”并不会自动产生这项能力；宿主取得材料后才可提供给执行模块。

若增加导入导出，导出模板定义及用户认可的样例，不包含服务配置、密钥或调用历史。导入按结构版本校验，保留原模板并以新 ID 处理冲突。此项可以晚于首版编辑和执行样例完成。

## 8. 与当前代码的衔接

本次读取的工作区已有名称、说明、instruction、纯文本 / Markdown、自定义保存校验、复制内置模板以及试用入口。无需重建编辑器。

优先增量工作：

1. 在前端与 Rust 的模板记录中一致加入 examples、缺项策略和修订信息；旧模板保留已有行为，旧模板不能因新增字段缺失而被拒绝。
2. 扩展统一消息组装，使实际执行与试用都传入完整模板；将前端样例展示与执行样例区分。
3. 迁移已有内置模板：原本要求待确认的模板显式保留该策略，避免全局规则调整后输出突然改变；新建自定义模板可默认省略空栏目。
4. 补充试用结果编辑和“保存为参考样例”；模板修改后提示当前试用结果来自旧版本，允许重试。
5. 用同一组真实口述验证无样例、有样例、缺项、数字 / 否定、样例事实串入和旧配置迁移。结构与迁移可以自动测试；模型成稿质量需要真实调用评估。

现有保存归一化会重建字段白名单，不能只给编辑器加输入框：否则新字段可能在校验或 Rust 保存时丢失。结构版本也要进入实际迁移判断，不能只修改版本号。
