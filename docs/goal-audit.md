## 确认的未完成项

### 1. 原生粘贴等待期间取消仍可能上屏

- `src/dictation/pipeline.js` 的 `cancel()` 只让前端任务失效。
- `src/App.jsx` 的取消操作还会结束录音与学习观察，但没有取消原生粘贴的命令。
- `src-tauri/src/lib.rs` 的 `paste_text()` 在准备 UIA 观察后继续进入 `paste_to_foreground()`，随后等待 70 ms 并发送 Ctrl+V，期间不检查任务是否取消。
- 因此取消发生在 UIA 准备（最多约 350 ms）、后台任务排队或剪贴板等待时，仍可能输入旧文字。前端检查只能阻止后续“完成”事件，不能撤回原生副作用。
- 本次使用可延迟完成的模拟后端重现：前端返回 `stage=cancelled`，模拟粘贴仍发生；这不是 Windows 实测。
- 关闭此问题需将取消标识传入原生投递，在写剪贴板和发送按键前检查，并对取消执行剪贴板清理。已发送到系统的按键无法撤回，验收应明确这个边界。

### 2. 构建交付缺失

本次检查下列目录均不存在：

- `dist/windows`
- `src-tauri/target/release`
- `src-tauri/target/x86_64-pc-windows-gnu/release`
- `src-tauri/target/x86_64-pc-windows-msvc/release`

已有 `WebView2Loader.dll` 是输入资源，不是完成构建的证据。PowerShell 打包脚本未在 Windows 执行；GNU 包是否需要额外运行库也必须在不含开发工具 PATH 的环境确认。

### 3. 自动学习仍有明确差异

当前学到的词只修正 ASR 返回的文字；未像上游 `PersonalVocabulary` 那样给识别服务提供词汇上下文。参考私有 ASR 的热词参数尚未验证，因此没有加入假定有效的接口参数。

此外，失焦即停止观察，尚未稳定 4 秒的修改不累计；最多处理 512 个差异 token；学习只跟随普通口述自动粘贴。这里应称为核心机制复刻，不能称为原版全量等价。

上游默认关闭的成稿挖词和未在本次明确要求中的风格画像，没有实现。它们与“读取用户纠正并记住术语”分别记录，不能混为一项。

### 4. 登录后启动是未实现的附加功能

`src/App.jsx` 中“登录 Windows 后启动”明确为禁用状态，未接入系统自启动。它不属于用户三项要求中的独立条目，但若将“复刻”解释为所有界面功能都完成，就仍需补齐。

## 本次已修复

粘贴失败此前会直接抛出异常，可能让界面一直显示“处理中”，并丢失本次结果入口。现在：

- 流水线发出 `paste-failed`，保留最终正文与识别原文；界面退出处理状态，把结果放入历史供复制。
- 失败的命令任务保留生成正文，不会把原始指令句当作正文输入。
- 取消/替换任务后的迟到错误不会写入旧结果。
- Rust 的 Ctrl+V 失败路径也会尝试恢复先前的文本剪贴板；仍只在剪贴板未被用户改动时恢复。

新增 3 项 JS 回归测试，覆盖正常任务失败、迟到失败、重试/主动插入原文失败。原生剪贴板行为仅通过编译，尚待 Windows 实测。此修复不包含上文的原生取消缺口。
