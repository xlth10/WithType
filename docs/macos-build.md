# Mac APP

Mac 原生适配基于 `6b8b860` 的墨滩第二稿和宣纸主题，保留 Windows 平台实现。

## 构建与打开

需要 macOS 14 或更新版本、Xcode Command Line Tools、Node.js 与 Rust。安装依赖后运行：

```bash
npm ci
bash build-macos.sh
open dist/macos/WithType.app
```

脚本按本机架构构建，产物位于 `dist/macos/WithType.app`，同时生成 ZIP 与 SHA-256。本机构建使用 ad-hoc 签名，没有使用 Apple Developer 证书或提交 Apple 公证。

## 首次使用

在「服务设置 → 语音服务」选择识别方式：可以配置 OpenAI 兼容服务地址、模型和密钥，也可选择「Apple 系统语音识别」及识别语言，无需语音 API Key。Apple 选项中的检查按钮只检查授权与本机模型能力，不录音、不代表已完成一次识别。首次检查或开始录音时允许系统语音识别权限，首次录音还需允许麦克风访问。拒绝后可在「系统设置 → 隐私与安全性 → 语音识别 / 麦克风」中允许 WithType。

Apple 模式通过 macOS Speech.framework 的 `SFSpeechRecognizer` 在本机识别，要求当前设备与语言支持设备端模型；不满足时明确提示，不会回退到联网识别。语言资源可在系统听写设置中检查。长录音和历史重识别会切成小于一分钟的识别段，沿用取消、失败恢复与历史记录。后续润色、翻译、提问等文字处理仍按文字服务设置发送文本。

点击录音或使用默认快捷键 `Control+Option+Space` 开始。自动输入需在「系统设置 → 隐私与安全性 → 辅助功能」中允许 WithType；没有权限时结果保留为可复制卡片。建议先将 APP 放入「应用程序」，再开启登录后启动，避免移动后启动项路径失效。

Mac 使用 CPAL/CoreAudio 采集，沿用重采样、分段识别、取消及 15 分钟上限。API 密钥存入 macOS 钥匙串；历史及录音暂存使用 AES-256-GCM 加密，加密密钥同样保存在钥匙串。

主控制页禁用 WebKit 的后台节流，保持托盘下的事件处理；HUD 和结果卡片沿用系统默认调度。动画 API 通过全局对象调用，避免丢失 WebKit 所需的窗口绑定。隐藏窗口完成初始化时直接结束动画，避免等待后台暂停的显示帧而让界面一直保持 inert。

自动输入在开始时保存 AX 焦点，完成后复核控件、可读正文及 UTF-16 选区，等待修饰键松开，再发送一次 Command+V。用户在处理期间复制的新内容优先保留；不向密码框或无法确认可写的控件自动输入，不对未确认的粘贴重复发送。无法读取正文时不能将发送按键称为已输入。卡片定位在 Mac 使用鼠标所在屏幕的工作区回退。

Mac 暂未实现粘贴后原输入框中的自动词汇学习；可以使用历史记录的「纠正并记住」或手动词典。界面中的自动学习开关在 Mac 禁用。

## 验证范围

2026-10-15 已生成 ARM64 Release APP 和 ZIP；签名完整性、压缩包 CRC/SHA-256、离线字体与外观资源校验通过。236 项 JS 测试通过，2 项 Windows 专用测试跳过；64 项 Rust 测试通过，包含 Mac 加密的往返/篡改拒绝及 UTF-16 选区插入计算。

打包验证过程中曾从 Finder 打开主界面、操作服务设置并枚举到系统麦克风。复测后台启动时发现 WebKit 动画 API 接收者及隐藏窗口播放问题，已修复并增加 API 接收者回归测试，同时关闭主控制页后台节流。最后一次冷启动的原生自动化读取返回 `AXError.cannotComplete` / 超时，因此最终包的冷启动、隐藏后后台存活、完整录音及跨应用自动输入仍未完成实机验收。没有将自动化超时当作通过，也没有据此认定应用进程崩溃。

完整的麦克风采集、模型服务转写及跨应用自动输入需要权限和用户配置的服务，不将源码检查或主窗口启动视为端到端语音验收。本次 Mac 适配源码留在当前工作区，尚未创建新的 Git 提交。
