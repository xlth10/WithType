# 输入交互与卡片定位实现

日期：2026-10-11。按用户确定的“光标优先；没有光标时在鼠标所在屏幕底部居中”规则实现，基于此前的 [交互审计](voice-input-interaction-audit.md) 修复核心投递与恢复问题。本说明描述源码行为，尚未完成 Windows 实机验收。

## 卡片位置

问答卡片和结果恢复卡片共用 `present_card` 与 `card_position::place`。

1. 优先查询 Windows UI Automation TextPattern2 的活动 caret range；退化文字范围没有矩形时，在克隆范围上扩展一个字符取得近似边缘，不改变用户选区。
2. UIA 不支持、队列繁忙或 250ms 内没有结果时，使用 `GetGUIThreadInfo` 的系统 caret。输入框的外框不会被当成文字光标。
3. 检测到光标：选择其所在显示器，在光标下方留 12 DIP；下方不足时放上方，并限制在工作区内。
4. 没有光标：选择鼠标所在显示器，在工作区底部居中，留 16 DIP 边距。鼠标位置/显示器无法查询时才退回主屏。
5. 卡片按目标显示器 DPI 换算物理像素，默认 420×320 DIP；小工作区限制尺寸。工作区排除了任务栏。
6. 同一 requestId 的卡片固定最初锚点，流式更新不会跟随鼠标跳动；关闭后清除锚点。新卡片重新定位。

创建卡片窗口时不请求焦点；卡片仍可点击和追问。长正文在内部滚动，长错误提示限制高度，底部操作保持可见。问答尚在生成时禁用追问与重新输入，仍允许复制已显示的文字。

## 投递与剪贴板契约

开始录音先调用 `capture_input_target`，与麦克风启动并行，避免较慢的 UIA 检查阻塞音频采集。前台窗口、子控件、进程和剪贴板序列号在排队与 UIA 查询前记录；工作线程再捕获 UIA 控件、可读取的正文与可获取的选区。排队期间前台身份变化时不授权自动输入。捕获超时/不支持时继续录音，完成阶段只复制结果；超时后晚到的目标只保留剪贴板基线，不授权自动输入。重试/重新转写也记录本次复制的基线。

自动输入需要满足：原窗口和控件仍有焦点、UIA 可以确认可写、原选区未移动（能够获取时）、原正文未变化（能够读取时）。原生投递统一在有界工作队列中串行执行。控件无法验证时使用复制回退；这不宣称控件物理上不可输入。

投递前等待 Ctrl/Alt/Shift/Win 松开，最多 500ms；超时只复制。准备学习观察可能访问 UIA，因此发送按键前再次检查目标、取消、修饰键和剪贴板序列号。发送后尝试读取目标变化验证正文落入；无法验证时保留结果卡片。

| 状态 | 含义 | 用户可见行为 |
| --- | --- | --- |
| `inserted` | 读取到与插入正文一致的范围变化 | 已输入；正文保留在剪贴板 |
| `sent` | 已提交 Ctrl+V，但无法确认文字落入 | 明确提示尚未确认；显示恢复卡片 |
| `copied` | 正文已写入剪贴板，没有确认输入 | 已复制，可以粘贴；显示恢复卡片 |
| `retained` | 复制/投递未完成或无法确认 | 正文保存在卡片与历史，可再次复制 |

默认最终正文留在系统剪贴板，取消了原来的纯文本备份/延迟恢复线程。这会替换录音前的剪贴板内容，不提供“完整恢复旧图片/文件/富文本”的承诺。处理期间系统剪贴板变化时，优先保留用户新复制的内容，语音正文改由卡片取回。显式点击复制结果会写入用户选择的那份正文。

`随便问`仍然只生成卡片，不自动写入剪贴板或其他应用。自动输入异常后会实际尝试复制回退；复制失败不会再显示复制成功。

## 恢复、取消和快捷键

- 最近完成结果从持久化历史恢复。新录音、失败或取消不会清空上一份结果；清空或按保留期删除历史后，相应结果不再可取回。
- 新增 `Ctrl+Alt+V`（可自定义）和托盘“复制上次完成结果”。快捷键冲突会提示，修改失败保留原绑定。
- 录音/处理期间临时注册 Esc 取消，空闲时释放；Esc 保留给取消，不能作为普通操作快捷键。注册失败会提示 HUD/托盘的取消入口。
- 主输入键可结束任何入口的录音；其他入口只结束自身录音。
- 重试文字、重新转写录音和“保留原文”只生成/复制结果，不把正文写入设置窗口。Ask 重试仍显示问答卡片。
- 卡片“3秒后输入”：先隐藏卡片并显示倒计时，给用户选择输入框的时间；结束时重新捕获目标并校验。取消会中止倒计时/投递。手动重新输入不启动自动词汇学习。
- 取消标记可先于投递登记，并且登记不会清除它。投递超时会阻止后续尚未提交的操作。系统已经接收的复制/输入不能撤回；已提交正文只归档，不重新弹卡片、更新最近完成结果或改动当前任务状态。
- 原生录音仍受 15 分钟上限约束；HUD 在最后一分钟显示剩余时间。设备中断/达到上限沿用已有保存与处理路径。
- 关闭流式问答卡片后，后续流更新和最终响应不会把同一张卡片重新弹出；完整回答仍保存历史。

## 对应审计问题

| 审计编号 | 本轮处理 |
| --- | --- |
| I1 目标切换 | 开始捕获、发送前复核；重试与投递分离 |
| I2 输入误报 | 区分按键发送与已确认输入，无法确认提供卡片 |
| I3 取消登记竞态 | 保留先到的取消标记，工作队列和提交前检查 |
| I4/I5 剪贴板格式/恢复竞态 | 明确默认保留正文，删除旧纯文本恢复线程；保护期间新复制 |
| I6 修饰键干扰 | 等释放、超时回退、发送前重查 |
| I7 复制失败反馈 | 复制结果结构化，失败显示保留与再次复制 |
| I8 粘贴失败缺少回退 | 真正执行复制回退、保存完整结果并显示卡片 |

选区内容用于模型改写/只读问答、任意工具执行、多组外接键盘绑定、音效与麦克风试音、HUD 翻译语言切换不在本轮实现。当前读取的输入框内容仅在本机用于目标校验与既有词汇学习，不加入 ASR 或文字模型请求。

- `npm run build`、Mac `cargo check --offline` 通过。构建仍有原有的大 chunk 提示。
- Windows x64 MSVC 目标：临时最小工程直接包含当前实际 `delivery`、`uia`、`card_position`、`correction_monitor` 源文件进行类型检查，通过。没有用替身实现代替这些模块；这不是整个 Windows 应用的链接或运行验证。
- 浏览器 420×320 预览检查：正文、反馈和底部操作可见；生成中的问答禁止追问/重新输入。见 [结果卡片截图](interaction-evidence/delivery-card-preview.jpg)。未录音、未发送模型请求。

| 无输入框、只读区域、密码框、不支持 UIA 的自绘控件 | 不发送未经校验的自动输入，复制/卡片回退 |

| 剪贴板占用、UIA 提供方超时、目标拒绝粘贴、管理员程序、终端、远程桌面 | 状态不夸大；完整结果可再次复制/输入 |
| 取消早于投递登记、等待修饰键时取消、复制已提交后取消 | 未提交操作被阻止；已提交结果归档且不更新新任务状态 |
| 从设置重试/历史重新转写，再点击“3秒后输入”并选目标 | 重试不误写设置；倒计时结束才检测并投递 |
| 重启后用快捷键/托盘复制；按 Esc 取消；15分钟上限前 | 上次结果可找回；取消可用；最后一分钟有倒计时 |

`SendInput` 的目标由操作系统在提交时决定，校验与提交之间仍有极小的切焦点窗口。剪贴板序列检查与写入也不是原子操作；队列拒绝捕获而未取得基线时，无法判断期间的新复制。UIA 的文字范围会受应用提供方、控件实现和双向文字影响；系统 caret 与混合 DPI 的位置也须实测。当前环境缺少 Windows C/C++ SDK，未生成或运行验收 EXE。
