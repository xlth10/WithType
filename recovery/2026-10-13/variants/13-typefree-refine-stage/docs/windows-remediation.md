# Windows 未通过验收处理方案

更新：2026-10-10。对应 [完整 Windows 验收清单](windows-acceptance.md) 与 [界面 / Skill 验收清单](design/windows-ui-skills-2026-10-10.md#windows-验收)。下表是失败后的处理路径；列出的源码修复方向须根据 Windows 复现证据实施，不能视为已发生或已验证的修复。

## 如何记录与复验

1. 记录失败编号、应用版本/提交、Windows 版本、每块屏幕的分辨率/缩放比例/排列、任务栏位置、设备名称、目标应用及触发步骤。
2. 保存界面截图、错误文案与历史耗时分项。窗口位置与焦点的诊断位于 `%TEMP%\typefree-debug.log`，几何行形如 `floating: work=(x,y) widthxheight scale=… -> Geometry …`；该日志不是完整的音频或网络请求日志。提交问题前移除密钥、私人正文和不必要的窗口标题。
3. 先按“现场处理”排除配置/环境问题；仍失败时按“源码定位 / 修复方向”修复并重新构建。涉及历史/暂存故障时先保留原文件，不通过删除配置或音频掩盖问题。
4. 使用原失败的屏幕、缩放、设备和目标应用重跑该编号，再复验同表相邻的成功/取消路径。只有复验达到“通过标准”，才把该项标为通过。

| UI-08 模型失败/取消仍粘贴，卡片模式误输入 | 在记事本用可识别的示例文本复现；分别测试卡片、自动输入开启/关闭 | `pipeline.js::finishTask/deliver` 保留失败与取消门禁；卡片分支不调用 `paste_text`；`lib.rs` 原生投递再次检查取消 | 失败指令、已取消文本不上屏；卡片只显示，输入分支遵守 autoPaste |

| UI-10 模型页仍分开、配置互相覆盖、测试状态误报 | 确认侧栏只有“模型配置”；先语音再文字独立修改/保存/测试，重启对照；浏览器预览不作为连接成功证据 | `App.jsx::ModelSettings/SpeechSettings`、`TextSettings.jsx`、`settingsMigration.js`：保留 asr/text 字段和两项凭据；只更新所属字段；参数变化清空测试状态，过期结果不标通过 | 同页两分区，独立测试和密钥；旧配置无需迁移或重填；重启保留 |

| B-03 重启丢配置/词库/凭据，密钥进入 JSON | 确认同一 Windows 用户、同一应用标识；检查配置目录可写；只复制非密钥配置，不跨用户复制加密历史 | `lib.rs::save_settings/load_settings`、`vocabulary.rs`、`text_api.rs`：保存失败须提示；密钥只用 `save_api_key/save_text_api_key`；检查持久化字段白名单 | 重启保留配置和规则；两服务凭据可用；settings.json 不含密钥 |
| B-04 登录启动不生效、关掉仍启动、移动便携版指向旧路径 | 在当前位置重新切换一次登录启动；用当前用户注销/登录检查；检查是否另有旧版启动项 | `startup.rs`：写当前 EXE 路径并正确引用含空格路径；关闭删除本应用项；设置失败不显示成功 | 开启启动当前 EXE，关闭不启动，搬移后入口更新 |

## 语音处理与恢复

| 编号 / 失败现象 | 现场处理 | 源码定位 / 修复方向 | 通过标准 |
| --- | --- | --- | --- |
| A-01 默认/USB/蓝牙采集失败，上传格式不对 | 在“模型配置”重新选择存在的设备；确认 Windows 输入设备未静音、桌面麦克风访问已允许；先排除断开的旧设备 | `audio.rs::list_audio_devices/build_stream/capture_loop/wav_bytes` 与连续重采样：适配实际通道、采样类型/频率；采集保留后端路径 | 各设备输出 16kHz 单声道 PCM16 WAV，不经 WebView 传整段 PCM |
| A-02 语音测试失败 | 检查 API 地址到 /v1、模型名和已保存的语音密钥，区分 401/403/404/格式拒绝；确认服务支持 multipart WAV | `lib.rs::test_connection/probe_wav/api_url`：请求 `audio/transcriptions`，表单含 file 和 model，检查返回 text 类型；保留 1 秒非静音测试音 | 接口接受测试 WAV 并返回 text 字段；空 text 仅证明接口连接，不证明识别质量 |
| A-03 没有分段、顺序错、停止后漏尾段 | 用超过分段目标时长且含明显停顿的语料；连续无停顿不作为强制切段要求；比较服务收到的段序号/时刻 | `audio.rs::pause_end`、`AsrOutcome` 收集和停止等待：保持采集连续、音频顺序提交，停止时等待在途段与尾段 | 停顿产生请求，连续说话不被硬切，最后正文按原顺序完整拼接 |
| A-04 中段失败丢音、尾段失败假成功、错误无法区分 | 先恢复网络/限流/服务权限，从“可恢复录音”或失败面板重试；不把认证失败当瞬时网络故障 | `audio.rs` 的确认位置与分段收集、`pipeline.js::classifyAsrError`、`lib.rs::transcribe_bytes_with_cancel`：失败段不推进确认位置，末段失败显式返回 | 中段未确认音频包含于后续请求；尾段失败可重试；错误类型区分 |
| A-05 静音仍上传、小声被过滤、5xx 没摘要或暴露密钥 | 检查设备静音/输入电平，换安静环境比较正常小声与尖峰；保留脱敏错误摘要，勿反复上传静音重试 | `audio.rs::has_voice/is_silent` 依据持续能量而非单尖峰；`lib.rs` 请求错误摘要脱敏，避免直接输出令牌 | 数字静音/孤立尖峰不请求且留暂存；真实小声通过；5xx 摘要脱敏 |
| A-06 中断后无法恢复、暂存明文、恢复不清理 | 用同一 Windows 用户重新打开恢复列表；先恢复设备/网络；保留失败的加密暂存，检查目录权限和磁盘空间 | `audio.rs::write_chunk/read_session/list_recoverable_audio/transcribe_native_audio`：DPAPI 加密、原子写入、恢复完成再清理；只承诺已落盘音频 | 强退后已落盘录音可恢复，无明文 PCM；成功恢复/明确丢弃后清理 |
| A-07 保留音频无效、到期残留、历史保存失败音频丢失 | 确认“保留后续录音”在该次录音前开启；查看对应历史及恢复列表，保存失败先修目录权限 | `history.rs`、`audio.rs::retain_native_audio/cleanup_history_audio`、`App.jsx`：以历史引用清理，保存失败不得释放唯一录音 | 可重新转写；期限/清空同步清理；历史失败录音仍可恢复 |
| A-08 识别更差、首字丢失、上传或等待太慢 | 用同设备、语料和网络比较增强开/关及安静/噪声；按历史编码/识别/整理/上屏分项定位瓶颈 | `audio.rs` 的启动、输入电平、分段与上传；确认无采集欠载，再针对设备或服务改善；WAV 256kbps 是当前选定接口，不自行改 AAC | 记录可复现质量/字节/延迟数据；修复后同条件重测，不以换原生采集推断更准 |

## 三个入口与投递

| 编号 / 失败现象 | 现场处理 | 源码定位 / 修复方向 | 通过标准 |
| --- | --- | --- | --- |
| E-01 快捷键变成按住录音、再次按键无效、未输入 | 先在普通权限记事本确认焦点、autoPaste 和快捷键注册；每次按下后完整松开 | `lib.rs` 全局快捷键 Pressed 处理、`App.jsx::toggleTask/startTask/stopTask`：按一次启动，再按一次结束；投递故障转 E-07 | 松开后继续录音，第二次按下结束并投递 |
| E-02 混按误停、快速连按或授权取消后麦克风占用 | 记录触发入口、开始/结束/取消顺序；确认录音结束后系统麦克风指示关闭 | `App.jsx` 的 trigger/generation/pendingStop 与 `useNativeRecorder.js`、`audio.rs::cancel_audio_session`：同入口才停止，迟到启动释放资源 | 混按不结束别的入口，启动期结束/取消可收敛，无占用遗留 |
| E-03 提问或动作走错去向、取消后迟到结果上屏 | 检查动作类型/技能结果去向，以记事本空输入框复现；记录取消时阶段 | `pipeline.js` 的 requestId 失效与 `deliver` 分支；`show_answer_card`、原生取消门禁 | 提问仅卡片，动作遵守设置；取消后无追加或投递 |
| E-04 SSE 不更新、普通响应为空、追问丢上下文、关闭仍流入 | 确认服务支持的响应形式；同一张卡连续追问；以新提问复验关闭后恢复 | `text_api.rs::stream_answer` 的 SSE 分片与普通 JSON 回退；`AnswerCard.jsx` 维护 messages/requestId 和取消 | 流式逐步显示；非流式完整显示；追问保留上下文；关闭停止追加 |
| E-05 短句/长句错误，文字超时丢原文，命令失败误输入 | 检查日常模式和文字配置；同一长句复现超时，另测提问/命令失败 | `src/text/localText.js`、`pipeline.js::finishTask/runTextStage`：普通口述保留原文回退；命令/提问失败不走原文投递 | 短句去末尾句号，长句按模式处理；口述失败有原文和提示，指令不上屏 |
| E-06 主/快速/备用路由不符、认证失败轮换模型 | 备用填写同一 endpoint 下的模型名；核对权限和故障类别，不把服务地址写成模型名 | `pipeline.js::callProcessText/classifyIntent`：判断/翻译优先快速；仅既定网络/超时/额度类别进入备用，认证阻断 | 顺序符合配置，主测试不代替快速/备用实际调用验收 |
| E-07 取消仍 Ctrl+V、剪贴板不恢复、强制粘贴失败卡住 | 先在普通权限记事本复验，受限编辑框改从历史复制；分别在 UIA 和剪贴板等待时取消；记录是否已发送 Ctrl+V | `lib.rs::paste_text/cancel_paste/paste_to_foreground`、`uia.rs`：每阶段检查 sessionId，恢复前比较剪贴板是否仍为本次文本；失败保留历史并退出处理 | 未发送时取消阻止投递；恢复不覆盖用户新剪贴板；失败可复制；已发送按键无法撤销 |
| E-08 快捷键冲突后旧键丢失、关主窗托盘失效 | 选择未被占用的组合，先确认失败提示再按旧键；通过关闭主窗而非退出菜单复验 | `lib.rs::replace_shortcut/register_shortcuts`：新注册成功才替换，失败回滚；主窗 CloseRequested 隐藏，退出菜单才结束进程 | 冲突保留旧键，主窗关闭后托盘和快捷键可用 |

## 自动学习

| 编号 / 失败现象 | 现场处理 | 源码定位 / 修复方向 | 通过标准 |
| --- | --- | --- | --- |
| L-01 纠正 4 秒后没有候选 | 确认普通口述自动输入、学习开关开启；保持同一可读输入框焦点；UIA 不可读时用历史“纠正并记住” | `correction_monitor.rs` 的观察周期/静置判断、`uia.rs` 投递锚点；避免把手动教学当自动候选验证 | 可读框纠正稳定 4 秒后触发候选 |
