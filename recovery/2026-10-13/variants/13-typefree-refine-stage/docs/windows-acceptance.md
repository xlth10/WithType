# Windows 验收 · 2026-10-10 更新

尚未执行 Windows 实机测试。下面给出确定步骤，避免把 Mac 的测试通过误认为 Windows 功能已经验收。

WASAPI 采集、DPAPI 暂存与历史、原生投递取消已加入源码，仍须在 Windows 上验收真实设备、服务和 UIA/剪贴板竞态。

每项编号对应 [未通过验收时的处理方案](windows-remediation.md)。界面与 Skill 的细项见 [界面验收](design/windows-ui-skills-2026-10-10.md#windows-验收)。失败项修复后需按同一环境重新验收，不能用浏览器结果替代原生结果。

## 构建和启动

- **B-01** 使用 README 的 GNU 或 MSVC 路径，检查 `typefree.exe`、WebView2Loader.dll、便携 ZIP、NSIS 与 MSI。
- **B-02** 在没有开发工具目录加入 PATH 的普通终端解压启动，确认依赖完整。首次安装、首次授权麦克风、第二次启动都应正常。
- **B-03** 退出后重新打开：模型配置、词库和凭据存在；不应把密钥写入 settings.json。
- **B-04** 开启「登录 Windows 后启动」，注销再登录确认托盘可用；关闭后再登录不应启动。移动便携版目录后检查注册表入口会指向当前 EXE。

## 语音处理与恢复

- **A-01** 使用默认麦克风、指定 USB/蓝牙麦克风各录一段；实际采样率可为 44.1/48 kHz，服务收到的文件必须是 16 kHz 单声道 PCM16 WAV，桌面链路不传整段 PCM 给 WebView。
- **A-02** 「模型配置 → 测试语音服务」发送一段 1 秒测试音频（低幅正弦，不是数字静音）到所填模型的 `audio/transcriptions`，确认服务接受 multipart WAV；服务返回空文字也算接口连接成功。
- **A-03** 录音含明显停顿时，在停止录音前可观察到分段请求；连续说话无停顿不强制按时长切断。停止后等待在途段与尾段，正文按音频顺序完整拼接。
- **A-04** 让中间段暂时失败，下一段应包含未确认的音频；让最后一段失败，界面应显示可重试而不是伪装成完整成功。401/403、429、格式错误与断网提示应可区分。
- **A-05** 整段静音或近静音的录音应被本地拦下并提示「录音里没有采集到有效声音」，不发出请求；录音仍留在暂存目录，可从「可恢复录音」重试。可观察到的两个边界：1 秒整段数字静音、以及整段静音里只有孤立尖峰的录音，都应被拦下；正常小声说话不得被拦下。服务端 5xx 提示应带上响应体摘要（密钥形如 `sk-…` 的令牌已打码）。
- **A-06** 录音中断开麦克风、关闭网络或强制退出应用；此前已暂存的音频应由当前 Windows 用户重启后恢复。检查暂存文件没有可直接听取的明文 PCM。恢复成功后清理；手动丢弃后文件消失。
- **A-07** 开启「保留后续录音」后，从历史重新转写；缩短历史期限或清空历史后对应音频一并移除。历史写入失败时音频仍可从恢复列表找到。
- **A-08** 用相同语料对比系统麦克风增强开关与安静/噪声环境，记录首字遗漏、词错率、上传字节和停止后的等待时间；不要仅凭原生采集推断更准。

## 三个入口

- **E-01** 记事本保持焦点，Ctrl+Alt+Space 按一次开始，松开仍录音；再次按下结束并输入结果。
- **E-02** 录音中按提问键不结束当前口述；同一按键快速再按、授权弹窗期间结束/取消，不得留下麦克风占用。
- **E-03** 提问只显示回答卡片；第三键的翻译/技能/命令按设置执行。处理期间取消，迟到结果不得再上屏。
- **E-04** 提问的 SSE 服务应逐步显示文字，卡片内可连续追问并保持上下文；不支持流式的兼容服务应完整显示普通响应。关闭卡片或取消时不再追加迟到文本。
- **E-05** 普通口述短句直接输出并去掉末尾「。」；长句按所选模式整理。使文字服务超时，应自动输入识别原文并提示原因；语音命令或提问失败不得输入原始指令。
- **E-06** 配置主、快速、备用文字模型，验证意图判断/翻译优先快速模型；网络或明确额度故障才进入备用队列，认证失败不自动换模型。
- **E-07** 分别在 UIA 准备、剪贴板等待阶段取消，确认原生后端未继续发 Ctrl+V。取消后若剪贴板仍是本次文本，应恢复先前文本；若 Ctrl+V 已经发送，系统按键无法撤销。强制粘贴失败时，应退出处理状态，历史保留最终正文供复制，并尝试恢复先前文本剪贴板。
- **E-08** 修改快捷键，尝试重复组合和被别的程序占用的键；失败应保留旧键。关闭主窗后托盘和快捷键仍可用。

## 墨珠 HUD

- **H-01** 以窗口自身的实际尺寸覆盖记事本，静音无波动，低音量时两侧也可见，任何时刻侧珠低于中央。墨珠遵循现有动效；HUD 可见底板为 176×54 逻辑像素，容纳墨珠、状态与控制按钮，原生透明窗口为 196×74（四周阴影边距 10）。
- **H-02** 开口/停顿/识别/完成的切换连续；启用系统减少动画后处理状态不持续游动。
- **H-03** 125%、150%、200%显示缩放、双显示器、取消和错误状态均无裁切。

## 自动学习

先用可控制转写文本的测试 ASR 或真实误识别，测试后在词库删除测试规则。

1. **L-01** 转写输出「明天联系徐向开会。」并粘贴到记事本，在同一输入框把「徐向」改为「徐翔」，停留4秒。
2. **L-02** 个人词库应只有候选「徐向 → 徐翔」（1/2），未正式生效。
3. **L-03** 再做一次独立口述、同样纠正；应进入已记住。重启应用，下一次「徐向」应本地改为「徐翔」。
4. **L-04** 删除该规则；后续相同纠正不再自动学入。历史记录的明确教学仍可以手动恢复。
5. **L-05** 「周四→周三」「他的→她的」「共5次→共4次」、改标点、删除/整句重写不应自动学入。
6. **L-06** 粘贴前后有原有文字，只改范围外文字不学习；焦点切换、密码框、读取失败、超长内容和重复不明区间都跳过。
7. **L-07** 连续两次口述，新一轮也能进入学习；取消观察后旧线程不得发出词条。
8. **L-08** 关闭学习开关后不新增候选，原有词仍生效；关闭自动输入或使用翻译/提问不观察输入框。
9. **L-09** 浏览器 textarea/contenteditable、VS Code 和常用聊天编辑框各测试一轮。UI Automation 不可读时，历史页「纠正并记住」仍应可用。
10. **L-10** 配置目录不可写时应提示未保存，不得显示“已记住”。不保存输入框全文。

## 已有 Mac 证据

- JS 单元与 pipeline 回归涵盖两次确认、候选到期、近音判断、手动优先、忽略记录、英文词边界、异步存储失败和录音取消。
- Rust 单元涵盖投递范围锚点、重复范围拒绝及 worker 生命周期；UIA API 已单独交叉类型检查。
- 浏览器预览实际验证了历史纠正保存、词库展示、重新打开后保留、删除及提示。`screenshots/vocabulary.png` 中的 macOS→macOSX 是一次性 UI 测试词条，已经删除。
- Mac 未验证 Windows 输入框可读性、全局快捷键、WebView2 录音许可和安装包启动。
