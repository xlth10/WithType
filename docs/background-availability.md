# 后台语音输入可用性 · 2026-10-12

本轮根据 [Typeless 后台调查](typeless-background-lifecycle-research.md) 增加原生生命周期监管。目标是关闭主界面后仍能输入，并能识别、恢复「托盘进程还在，但语音页面已经不可用」的状态。实现采用本项目的 Rust/Tauri 接口，没有复制 Typeless 的产品代码。

## 用户可见行为

- 已配置语音模型时，登录启动只进入托盘，不闪现设置窗口。首次配置和手动启动显示主界面；手动再次打开应用仍能打开设置。
- 关闭设置窗口保留托盘、原生快捷键和语音页面。闲置时不启动麦克风，不阻止 Windows 睡眠。
- 托盘提示和主界面显示输入是否就绪；未就绪时按原生快捷键会显示 HUD 错误。托盘新增「恢复语音输入」，界面故障状态也有恢复按钮。
- 睡眠、锁屏或页面恢复会结束当前录音/处理，保留已暂存音频，并取消旧任务的文字请求和投递。唤醒、解锁后重新注册快捷键，页面完成就绪握手后接受新的录音；不会自动续录、重新输入或重放上次按键。
- Windows 任务管理器禁用启动项后，应用不会在下次启动时自动重新开启它。打开设置时重新读取系统状态；用户明确开启开关才清除本应用的禁用标记。
- 等待清空历史、丢弃录音的确认弹窗时暂缓健康检查，最长十分钟；弹窗期间不接受新的语音入口，避免阻塞 JavaScript 被误判为失联。

## 原生监管与恢复

Rust 的 `background::Supervisor` 保存控制器代次、状态、待确认动作和任务集合。现有 `main` 页继续承载语音流水线，窗口是否显示不影响它的生命周期。录音采集和系统输入仍由原生后端完成，本轮没有整体拆分或重写现有流水线。

前端先安装动作、健康探测、状态、重置四组监听，再载入配置、自定义技能、历史与词库，全部成功后报告就绪。载入失败会暂停输入并显示原因，避免拿默认值覆盖无法读取的数据。

快捷键、托盘、HUD 与主界面共用动作入口。每个动作携带代次与唯一编号，前端领取后才能执行；重复、超时或旧代次的动作不执行。任务在录音、目标捕获或模型请求前注册，结束后释放；原生录音和输入操作再次核验任务身份。

| 检测/限制 | 当前实现 |
| --- | --- |
| 健康探测 | Rust 每 5 秒发事件，前端通过 IPC 回应；不依赖隐藏页面的 JavaScript 定时器 |
| 已就绪页面失联 | 30 秒无回应后，在下一个探测周期开始恢复 |
| 初始化未完成 | 最长 60 秒；页面能回应健康探测也不能无限停留在准备阶段 |
| 动作没有领取 | 超过 4 秒在下一个探测周期触发恢复；不自动重放该动作 |
| 自动恢复次数 | 5 分钟内最多 3 次，随后停止自动恢复并提示手动恢复 |
| 恢复方式 | 首先重载主语音页面；窗口不存在、重载报错、恢复后仍未就绪或用户手动恢复时，重建三个 WebView |
| 明确退出 | 先停止监管并撤销任务，再退出；排队中的窗口重建不能继续恢复旧代次 |

恢复会先撤销任务、停止学习观察与临时按键捕获、释放录音设备、收起 HUD，再初始化页面。旧页面迟到的模型响应、投递与取消清理受到代次/任务/音频中断标记限制。正常取消仍清理录音；系统中断保留已经写入的音频，并尽力写完当前采集尾段；明确丢弃允许删除它。

Tauri 默认在最后一个窗口销毁后请求退出。本应用对没有显式退出码的窗口生命周期请求保留托盘进程，因此重建全部 WebView 不会使应用自行退出。用户退出与系统会话结束进入停止状态。

Windows 使用隐藏顶层消息窗口接收电源与会话事件，睡眠和锁屏分别记录，只有两者都解除才恢复就绪流程。登录时会话通知注册失败会定时重试。系统事件来源见 [WM_POWERBROADCAST](https://learn.microsoft.com/en-us/windows/win32/power/wm-powerbroadcast)、[WTSRegisterSessionNotification](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsregistersessionnotification)。

登录入口为当前用户的 Run 项，命令带 `--background`，同时读取 StartupApproved 状态。已有本应用启动入口仅迁移参数，保留系统禁用状态；实现参考了 [Electron 对 Windows 登录状态的处理](https://github.com/electron/electron/blob/main/shell/browser/browser_win.cc)，这是平台实现依据，不是 Typeless 的 Windows 运行证据。

## 已验证与边界

2026-10-12：173 个 JavaScript 测试、37 个 Rust 测试通过；前端生产构建与视觉基准校验通过。新增测试覆盖初始化就绪、迟到动作确认、旧代次拒绝、睡眠/锁屏组合、恢复次数、退出、阻塞确认弹窗、任务注册中取消、失效的技能预览，以及文字请求子任务取消。

Windows x64 隔离类型检查通过：使用真实的 Windows API 与 CPAL 依赖编译本项目 `startup.rs`、`audio.rs`、`background/windows_events.rs`；其中 Tauri 命令和宿主由最小桩替代。完整 Tauri 接线由 Mac 的实际依赖编译验证。隔离检查不能证明 Windows Tauri 运行、驱动行为或消息送达正常。

尚未执行 Windows 实机的长时间闲置、睡眠/休眠、WebView2 进程故障及启动项测试。当前 Mac 缺少完整 Windows C/C++ SDK，不能产出并验收完整 Windows EXE。

恢复范围是仍在运行的原生宿主及其页面/任务。没有外部 watchdog 或 Windows Service，主进程被杀死/崩溃后不会自行复活；明确退出会停止恢复。自动重载/重建会丢失尚未保存的页面草稿；已落盘配置、技能、历史和录音沿用现有存储。强杀进程时只能恢复已经成功写入的音频，不能保证未落盘的尾段。

## Windows 验收矩阵

使用测试文本和可控制服务，在记事本及实际使用的软件里记录每一步的入口收到、录音开始、处理结束和投递时间；异常用例只结束指定进程，不清理用户配置。

| 用例 | 预期结果 |
| --- | --- |
| 关闭设置后连续调用 20 次 | 三个入口、停止、取消、复制上次结果都可用；没有多开录音 |
| 隐藏主界面，闲置 8 小时/24 小时 | 首次按键能录音；记录 CPU、内存、设备占用与起录延迟 |
| 登录启动/手动再次启动 | 已配置时登录不闪主窗；手动启动显示设置，只有一个宿主实例 |
| 任务管理器禁用启动项后手动运行 | 设置反映禁用；再登录不启动；明确开启后恢复启动 |
| 录音中锁屏，随后睡眠；先唤醒再解锁 | 保持暂停直到两个条件解除；旧任务不投递，音频可重转写 |
| 空闲时睡眠/休眠/解锁 | 不因长睡眠误判失联；就绪后按键可以重新录音 |
| 中断发生在录音、ASR、文字请求或投递准备阶段 | 麦克风释放；旧响应不启动新的系统输入；中断录音可恢复 |
| 重载主页面；结束本应用的 WebView2 renderer/browser 子进程 | 原生托盘保留；自动恢复有界；失败可从托盘手动恢复 |
| 连续让页面初始化失败 | 停止自动循环；显示失败和恢复入口；默认数据不覆盖原数据 |
| 删除确认弹窗停留超过 30 秒再取消 | 页面不被自动重载，原操作未执行，语音入口重新可用 |
| 唤醒后快捷键被其他应用占用、切换或拔插麦克风 | 提示冲突/设备错误，可通过设置或托盘修复，不续录 |
| 明确退出、杀死主进程 | 明确退出后不自动重开；主进程强杀符合上述恢复边界 |

原生监管见 `src-tauri/src/background.rs` 与 `background/`；前端握手见 `src/dictation/controller.js`。完整设备、输入和构建验收继续使用 [Windows 验收说明](windows-acceptance.md)。
