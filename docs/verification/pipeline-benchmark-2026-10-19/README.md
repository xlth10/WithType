# Mac 处理链路真实服务对照（v1）

2026-10-19，在 Apple M4（10 核、16 GB）、macOS 27.0.1 上，以同一组 **16 条合成语音 WAV** 交错执行：基线第 1 轮 → 优化第 1 轮 → 基线第 2 轮 → 优化第 2 轮。共完成 64 次实际 Apple 本机 ASR、56 次实际文字模型请求。文字主模型与快模型均沿用现有 **deepseek-flash**，温度 0.2，未换模型。

基线固定为 534b3d7；优化源码尚未提交，因此每轮都记录了源文件 SHA-256，见 [score-v1.json](score-v1.json)。四轮音频 SHA-256 相同。正式测量前已经进行 ASR 和文字服务烟测，不能称作冷启动数据。

| 轮次 | 完成 | 局部自动检查通过 | 固定音频文件提交到完整成稿 p50 | p95 |
|---|---:|---:|---:|---:|
| 基线 1 | 16/16 | 8/16 | 3489 ms | 11578 ms |
| 优化 1 | 16/16 | 10/16 | 1513 ms | 9223 ms |
| 基线 2 | 16/16 | 8/16 | 1960 ms | 5566 ms |
| 优化 2 | 16/16 | 9/16 | 1631 ms | 9668 ms |

这些是固定小样本的局部断言结果，**不是总体准确率**。评分规则在四轮中没有修改；规则漏报由人工复核单列。两轮服务等待存在明显波动，优化第二轮的尾延迟高于基线第二轮，不能据此宣称稳定提速。

本轮能确认的变化：

- 短句“明天三点，不对，四点开会”在基线直接保留改口过程；优化两轮均输出“明天4:00开会。”。
- 数字改口在优化中保留最终 10200 元、20 个；第二轮还显式否定旧数 12000，事实正确，但未完全删掉改口痕迹，被禁止旧数的局部规则判为失败。
- 真正传入 Apple contextualStrings 后，“翟云”→“翟昀”、“生间”→“声笺”、“HD PP”→“HTTP”；“岑溪”仍识成“晨曦”，WithType / Qwen ASR / Apple Speech 仍有错误。热词只是提示。
- 日期句“周三发版改成周四”两轮都进入文字模型，但仍原样输出，尚未收敛为最终安排。
- “预览”→“玉兰”、“不能只展示成功结果”丢失“只”等 ASR 错误在后续成稿中保留；需要如实保留这个边界，不能要求提示词猜回原音频事实。

详细原始输出与人工复核见 [manual-review-v1.md](manual-review-v1.md)。每轮完整事件、ASR 文本、词库处理后文本、模型成稿和耗时均保存在各目录的 results.jsonl。

## 口径与限制

- 主延迟指标是**固定音频文件提交到完整成稿**。harness 在提交现成音频前标记 stoppedAt，没有测录音中预识别，不能叫实际松手等待或松手到上屏。
- ASR 使用独立授权、由 LaunchServices 启动的 Speech probe，复用产品 Objective-C Apple 桥。文字使用产品 Rust 客户端和已有系统凭据库。没有导出或记录密钥。
- 复制与上屏被结果收集器替代，**没有验收 WithType 麦克风采集、快捷键、真实输入框、焦点或系统投递**。
- 合成语音发音、连读、英文读法不能代表真人；同一个模型的两次输出也可能变化。这里只验证链路和这些素材上的现象。
- 文字调用关闭流式预览和录音中增量整理，以隔离完整成稿；不能代表生产 UI 的首字预览速度。
- 用户没有 Windows 环境，且明确 Windows ASR 没有真实服务地址；Windows 服务与客户端实测本轮暂缓，未用 Mac 代替验收。
