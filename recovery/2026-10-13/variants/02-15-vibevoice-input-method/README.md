# 项目 15：VibeVoice 本地语音输入法

面向 macOS Apple Silicon 的本地按键录音输入工具。它使用微软 VibeVoice 项目体系中的
`VibeVoice-ASR-BitNet` 模型和官方 `VibeASR.cpp` CPU 运行时，在本机完成识别；音频不上传云端。

## 工作方式

1. 把光标放进任意文本框。
2. 按 `⌥ Space` 开始录音。
3. 再按一次 `⌥ Space` 结束录音。
4. 应用在本机转写，按所选模式整理文字，再尝试粘贴到原输入位置。

快捷键触发后，屏幕底部会出现一条无背景、不抢焦点的极简流体声纹：录音时，暖色液体会随
真实麦克风音量呼吸和流动；结束录音后，冷色流体持续迁移，表示本地转写仍在进行。
界面不显示状态文案、计时或虚假的百分比；完成短暂反馈，失败标记保留以便恢复。详细状态可
在菜单栏与 VoiceOver 中获取。周围窗口保持完全透明，系统开启“减少透明度”时才自动回退
到高对比度底板；“减少动态效果 / 增强对比度”设置也会即时生效。

悬停流体区域会显示停止、取消或复制按钮。正常录音可按 Esc 取消，也可从菜单取消；
全局 Esc 监听依赖系统的按键监听权限，菜单与悬停按钮不依赖该监听。窗口不获取键盘焦点。

## 文字整理、词典与恢复

菜单栏提供五种模式：原文（默认、完全本地）、本地术语纠错、轻度整理、翻译为英文、语音修改选中文字。
后三种 AI 模式需要在“文字整理与词典设置”中填写兼容 Chat Completions 的完整接口地址、模型名、
API Key。HTTPS 服务或 localhost / 127.0.0.1 本机 HTTP 服务均可使用。API Key 存入 macOS 钥匙串。
应用运行后，再次双击应用可直接打开设置（录音或处理期间不会打断当前会话）。
更换接口地址且不填写新密钥会清空旧密钥，避免把旧凭据发送到新服务。该接口未绑定特定模型供应商。

个人词典支持普通专有名词，也支持“正确写法=误写1|误写2”的确定性纠错规则。纠错采用单遍、
长词优先替换，不会在英文长单词内部误命中。AI 模式只发送转写和结构化词典；编辑模式额外发送
选中文字；应用上下文开启后只发送 chat、email、code、document 或 generic 类别，不发送原始应用名。
音频始终在本机处理。词典暂时不会直接影响 VibeVoice 声学识别。

轻度整理会识别句首或句尾的“用英文 / 用日文 / 用韩文 / 用中文”等确定性语音口令；否定表达和
句中出现不会误触发。没有改口或口头禅的短句会跳过模型。模型输出会检查空结果、助手式前缀、
异常扩写和数字遗漏：普通整理失败会回退到本地纠错后的识别文字，翻译和编辑失败不会自动覆盖目标文本。

本地历史最多保留 50 条，包含原文、结果、模式及识别／整理耗时，位置为
`~/Library/Application Support/VibeVoiceInput/history.json`（文件权限 0600）。菜单点选条目即可复制；
“用当前模式重新处理上次口述”只生成可复制结果，不会自动向前台应用输入。编辑模式需重新选中文字录音。

写入前检查原应用、可访问的输入控件、选区和文本内容。目标变化或无法确认时不自动粘贴，结果仍可复制。
发送粘贴后约一秒恢复原剪贴板，期间用户更改剪贴板则不覆盖。发送按键并不等于目标应用确认接收；
菜单会明确显示“已发送粘贴”，所有结果均可从历史找回。部分不提供辅助功能文本信息的应用需要手动复制。

录音最长 180 秒，随后自动转写；识别等待上限 120 秒，文字整理请求上限 25 秒。
取消识别会终止该推理进程并重新载入模型，取消后需等待重新就绪。录音临时文件在完成、失败或取消时清理。

## 模块与验证

- `AudioRecorder.swift`：录音与音量反馈。
- `LocalSpeechRecognizer.swift`：识别接口和 VibeVoice 常驻进程适配，按完整 UTF-8 行解码。
- `WritingPipeline.swift`：文字模式、兼容接口、钥匙串及本地历史。
- `TextInsertion.swift`：输入目标校验与剪贴板恢复。
- `main.swift`：会话、取消、超时、设置和菜单。
- `VoiceHUDController.swift`：透明流体和悬停操作。

运行 `swift test` 验证接口响应、URL 范围、上下文开关、UTF-8 分块、历史恢复和无目标拒绝写入。
当前仍使用完整 WAV 的 CPU 识别；尚未实现流式音频输入、其他识别后端、自动应用规则和性能加速。
增加了分阶段耗时记录，便于后续基于实测选择优化方式。

这是系统级“听写助手”，不是注册到 macOS 输入法列表中的 InputMethodKit 键盘。VibeASR.cpp
按 WAV 文件处理，因此结束录音后才开始转写，不会在讲话过程中逐字上屏。

## 目录

- `upstream/VibeVoice-main`：微软 VibeVoice 上游源码快照
- `runtime/VibeASR.cpp-main`：适合 M4 的官方 CPU 推理运行时
- `Sources/VibeVoiceInput`：本项目的 macOS 菜单栏应用
- `dist/VibeVoiceInput.app`：构建后的应用

## 构建

```bash
./scripts/build_runtime.sh
./scripts/download_models.sh
./scripts/build_app.sh
```

需要 `CMake`、Apple Clang、Swift、`wget` 与 `ffmpeg`。模型约 1.58 GB，下载脚本支持断点续传，
并会校验官方 SHA-256。首次启动会载入模型，需要稍等。菜单栏麦克风显示“就绪”后即可使用。

## 首次权限

系统会请求两项权限：

- 麦克风：录制待识别语音
- 辅助功能：模拟 `⌘V`，把识别结果粘贴到当前文本框

`⌥ Space` 使用 macOS Carbon 系统热键，不依赖辅助功能或输入监控权限。首次按下快捷键时会请求
麦克风权限；首次完成转写时才会请求辅助功能权限。

在“系统设置 → 隐私与安全性”中允许 `VibeVoiceInput`，更改权限后重新启动应用。
如果没有辅助功能权限，识别结果仍会保留在剪贴板中，可手动粘贴。

## 热键回归测试

先退出 `VibeVoiceInput`，再运行：

```bash
./scripts/test_hotkey_manager.sh
```

通过时输出 `PASS: Carbon received ⌥ Space`。

## 启动

```bash
open ./dist/VibeVoiceInput.app
```

若从非标准位置运行开发二进制，可设置：

```bash
VIBEVOICE_PROJECT_ROOT="$PWD" ./.build/release/VibeVoiceInput
```

## 性能预期

微软公布的 Apple M4（16 GB）测试中，4 线程 RTF 约为 0.43；即 10 秒音频的纯推理时间
约 4.3 秒（另有模型预填充和文件处理开销）。默认使用 4 线程，在速度和系统响应之间取平衡。

本机安装验证使用上游自带的 17.28 秒中文音频：持久化服务总推理约 10.7 秒，RTF 0.62，
成功输出中文文本。真实速度会随录音长度、温度与后台负载变化。
